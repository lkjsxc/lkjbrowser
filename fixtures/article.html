The web, one readable page at a time

A dispatch from the workshop   ·   November 17, 2026   ·   6 minute read

A browser begins with a small promise: ask for a page, give its words room to breathe, and let a reader follow their curiosity.

We have become used to thinking of the web as a complicated machine. It is also a remarkably simple idea. A document can point to another document, and a person can decide where to go next. A good reading experience keeps that path visible.

This page is an exercise in those essentials. Its headings, paragraphs, bold emphasis, italic asides, and ordinary links are laid out and painted by the same small program that fetched the document.

Start with space

Legible text needs more than recognizable letters. A comfortable measure gives each line a sensible ending. Consistent baselines make a paragraph feel settled. Enough space between sections helps the eye find a place to begin again.

“The useful question is not how much can fit on a screen, but how easily someone can find the next thought.”

There is no animation here, and no script is needed to read the article. The interesting work happens underneath: a font file becomes curves, curves become coverage, and coverage becomes the dark edge of a letter against the page.

Four ingredients for a useful page

  • A clear hierarchy. A title explains the subject; section headings divide the argument into places a reader can return to.
  • A human reading width. Lines wrap before they become a journey across the whole window.
  • Links with a destination. Try the workshop page, then return here to continue reading.
  • An honest response to failure. An unreachable page should explain what happened and leave a useful way forward.

From bytes to a page

The route is deliberate. First, the program reads bytes from a file or a TCP connection. It recognizes a small subset of HTML and builds a tree. CSS rules then attach presentation choices to that tree. Finally, the layout pass creates rectangles and text fragments with explicit positions.

  1. Read the document and decode its character references.
  2. Apply supported selectors and inherit text properties.
  3. Lay out block boxes and wrap inline text using real font metrics.
  4. Rasterize each outline and present the resulting frame.

That last frame is not a picture of somebody else's browser. It is the direct output of the program. Resizing the page changes the line breaks; scrolling moves through the document; clicking a link loads another page.

Leave room for the next step

A first browser is not a complete web platform. Some layouts are too ambitious for it, some fonts need shaping it has not learned, and many sites require protocols or scripting beyond this first slice. Being specific about those boundaries makes the next improvement easier to choose.

For now, a long article can be read from beginning to end. That is a small, useful place to start.
