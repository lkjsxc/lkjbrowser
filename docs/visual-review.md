# Visual review record

All page pixels below were generated by the native lkjscript browser. No browser engine,
font renderer, image library or screenshot editor draws the page for it.
The compositor screenshots are separately captured by Weston's screenshot client.

## Round 1: actual window and first full pages

Opened `shots/wayland-article-r1.png` from actual Weston 13 and the program's
`simple-r1.png`, `error-r1.png`, and `article-scroll-r1.png`.

- Article baselines, paragraph rhythm, wrapping, bold/italic runs and list markers were readable.
- The error panel crowded the paragraph immediately beneath it; the page unnecessarily scrolled.
- The simple-page lead ended with a lone word, and its long caption described implementation details.

Fixes: error margins changed from 64 to 48 px, panel padding from 30 to 24 px,
an explicit 24 px bottom margin was added, and paragraph spacing tightened.
The lead was rewritten with a deliberate line break; the caption now reads naturally.

## Round 2: PNG page, error spacing and narrow widths

Opened `error-r2.png`, `simple-r2.png`, and `narrow-r2.png`.
The actual decoded landscape was visible. The error page now fits the viewport with
comfortable space under the panel. The simple-page copy fix was still pending in that
snapshot, so it was applied and re-rendered.

A long address in a narrower viewport needed a visible truncation marker.
The address and status text now use a real ellipsis; an edited long address shows its end
so the character being typed remains visible. The 420 px review exercises this.

Code review alongside the pictures caught incorrect font-relative percentage box dimensions,
inheritance of unitless line-height, and a word split at a bold/normal style boundary.
Unsupported box percentages are ignored; supported relative font metrics now inherit correctly;
one word crossing style nodes is moved together when it fits on the next line.

## Round 3: confirmation

Opened `simple-r3.png` and `narrow-r3.png` after the fixes.
The lead has balanced lines, the image and caption are distinct, the card text is readable,
and the narrow article wraps its title and paragraphs cleanly. The address ellipsis is visible.

An actual HTTP fetch of example.com was also inspected. The current response contains one
paragraph and a script, without the heading/link seen in older versions of that page.
Its sparse screenshot follows the received HTML; JavaScript is intentionally not executed.

Final reviewed captures and deterministic layout/pixel baselines are documented in README.

## Final compositor and motion review

Opened the final `shots/article.png`, `shots/simple.png` and `shots/error.png`
after the CSS arithmetic/cascade and underline repairs. Link underlines now cover the spaces
within each visual run, without joining distinct anchors or crossing line breaks. Two targeted
layout cases cover ordinary/bold words, wrapping and separate links with the same destination.
The page margins, baselines, paragraph spacing, image caption and error recovery link are clear.
All three compositor screenshots match the native browser PNG at every pixel (1000 by 760).

Opened frames 005, 009, 011 and 015 from the final continuous recording. They show the scrolled
article, Home, the clicked workshop page, and the return to the article. The same native process
stays open throughout; six application events produce seven submitted frames. The 16-frame APNG
preserves the actual Weston screenshots and uses a nominal 400 ms delay. These are scripted
application events; physical-device input is not claimed. Protocol input has its separate native
Wayland peer proof.
